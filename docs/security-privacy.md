# Security, privacy, and resilience

This project is an educational, single-operator batch-analysis demo. The Phase 9
controls reduce the risk of malformed input, accidental data retention, unsafe
exports, and vulnerable dependencies; they do not turn the application into a
multi-tenant production security service.

## Trust boundaries

- Uploaded CSV and JSON values are untrusted. The API accepts only the documented
  prediction routes, schema, UTF-8 CSV encoding, finite numeric features, and bounded
  row/column/byte counts.
- Model artifacts are trusted deployment inputs, not user uploads. Startup accepts an
  exact six-file artifact directory, rejects symlinks and extra entries, verifies file
  sizes and SHA-256 hashes, then checks cross-file versions before `joblib` is allowed
  to deserialize the pipeline.
- The React client treats every API response as untrusted and validates the API-v1
  shape before rendering or exporting it.
- CORS is an explicit HTTP(S) origin allowlist. Wildcards, credentials embedded in an
  origin, paths, duplicate origins, and an empty allowlist fail startup. CORS is not
  authentication.

## Input and resource controls

The default request boundaries are configurable through the documented `IDS_*`
environment variables:

| Boundary | Default |
|---|---:|
| CSV file bytes | 10 MiB |
| CSV rows | 10,000 |
| JSON records | 1,000 |
| CSV columns | 120 |
| Validation and inference deadline | 15 seconds |

The outer ASGI request guard enforces a body limit even when `Content-Length` is
missing. CSV parsing checks the deadline and row limit while iterating instead of
materializing an unbounded parser result. Filenames containing paths, non-CSV
extensions, unsupported media types, archives, non-UTF-8 bytes, NULs, duplicate or
missing headers, non-finite values, and inconsistent row widths are rejected with a
stable error envelope. The proxy adds its own body and I/O timeouts.

These are application limits, not a full denial-of-service perimeter. An internet
deployment still needs upstream connection/rate limits and capacity controls.

## Data handling and logs

- The service does not persist uploaded rows, predictions, or exported results to an
  application database or application directory.
- Multipart bodies may cross Starlette's in-memory spool threshold. Every upload is
  explicitly closed in a `finally` block; the hardened container mounts `/tmp` as a
  size-limited temporary filesystem that disappears with the container.
- Normal access logs contain only a generated request ID, HTTP method, route, response
  status, and stable error code. They exclude filenames, headers, query strings, row
  identifiers, feature names, values, and response bodies.
- Request IDs are generated by the API. A caller cannot choose the value that appears
  in logs or error envelopes.
- CSV exports neutralize cells beginning with `=`, `+`, `-`, `@`, tab, or carriage
  return before RFC-style CSV quoting, preventing user-controlled row IDs from being
  interpreted as spreadsheet formulas.

Network-flow metadata can still be sensitive even though the model contract excludes
IP addresses, direct identifiers, timestamps, source ports, and destination ports.
Packet sizes, counts, timing distributions, activity levels, and model classifications
can reveal system behavior. Operators should minimize collected rows, obtain the
required authorization, use TLS outside localhost, protect downloaded exports, and
delete them according to their own retention policy.

## Runtime hardening

Both images declare non-root users. Compose starts them with a read-only root
filesystem, all Linux capabilities dropped, `no-new-privileges`, and a bounded `/tmp`
tmpfs. The model volume is read-only. Nginx applies a restrictive content security
policy, clickjacking protection, MIME sniffing protection, a no-referrer policy,
disabled browser capabilities, and no-store caching.

## Security gate

Run:

```bash
make security
```

The command performs the hostile-input and spreadsheet-export tests, audits the exact
Python and npm locks, scans committed history and the working tree for secrets with a
pinned Gitleaks container, builds both images, verifies their configured and effective
runtime users, and scans socket-free image archives with pinned Trivy. Critical,
fixable high, unknown, and expired-exception findings fail the command. Scanner
containers never receive the Docker socket;
Gitleaks runs without network access and with the repository mounted read-only.

Security advisory data changes over time. A previously passing checkout must rerun the
gate before release. Any exception must identify the advisory, affected component,
reason it is not exploitable or not yet fixable, owner, expiry date, and compensating
control in the Phase 9 security report.

## Accepted residual risks

- `joblib`/pickle deserialization is unsafe for untrusted files. Integrity checks do
  not establish provenance if an attacker can replace both an artifact and its
  manifest, so only artifacts produced by the documented pipeline and delivered
  through a trusted channel may be mounted.
- There is no login, authorization model, audit database, tenant isolation, or
  application-level rate limiter. Keep the demo on localhost or behind an authenticated,
  TLS-terminating, rate-limiting gateway.
- A timed-out native model call cannot be forcibly interrupted safely inside the Python
  process. The deadline prevents a late result from being returned; container-level
  CPU/memory quotas and upstream timeouts remain necessary for hostile public traffic.
- CIC-IDS2017 is a controlled 2017 dataset. Model error, concept drift, evasion, and
  low-support attack families remain operational risks; predictions require analyst
  review and must not trigger autonomous blocking.
- Jost is packaged locally under the SIL Open Font License, so the runtime page makes no
  third-party font request. The browser still has a system sans-serif fallback if the
  local asset cannot load.
